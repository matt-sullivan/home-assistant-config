Likely cause: disabling the persistent system packages `com.android.bluetooth` / `com.android.se`. Recovery needs USB adb. Lesson: never `pm disable-user` persistent system packages; disable one package at a time and reboot to test. Recovery (LineageOS recovery) can't decrypt `/data/system` (FBE), USB adb doesn't start during the hang, `/data/property` is encrypted and `system` is a logical partition in `super` (read-only), so the package state can't be edited offline; `console-ramoops-0` held only a corrupted log from the previous boot. Android 17 protects `package-restrictions.xml` and its `.reservecopy` with fs-verity (in-place write gives EPERM; a replaced unprotected main file is discarded in favour of the reserve copy), so both files were replaced with the edited ABX while stopped; it booted at 12:55. Cleanup: rescue `.rc`/script and the PC key were removed from recovery (`system`/`product` are read-only while Android runs, even for root with `blockdev --setrw`); `e2fsck -n` clean. Android re-applied fs-verity to both package-restrictions files on its next write. USB debugging stays on (`persist.sys.usb.config=adb`); Bluetooth stays off.
